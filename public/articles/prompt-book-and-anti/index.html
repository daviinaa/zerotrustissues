The prompt book and the anti book

4 min read

Most companies have given their people AI tools. Not every employee knows how to get what they want from them, or what to expect them to do.

Say you are given a task. You are not as familiar with the codebase as the next engineer, and you need to know what to ask to get what you want. Somebody probably solved a problem like yours a few weeks ago. What did John ask when he was working on this? You could take his prompt and tweak it, or make it better.

The prompt book

So I want a company prompt book. Not a book as such: a shared wiki of prompts. Each entry is a markdown file with what someone asked, what it was for, and what they would change next time. Anyone can copy one and improve it, and the improved version goes back in. It starts with one team and can grow to the whole organisation.

The anti book

The opposite of the prompt book is what I call Anti. The prompt book helps John ask the right question. Anti stops him asking the wrong one: the question that would break production or development, or harm the company. It is a set of markdown files that say what not to do.

There is a limit here. A markdown file is advice to the model, not a lock. The model usually follows it, but nothing forces it to. For rules that must hold, the block has to be enforced outside the model. That is what guardrails as code is for.

Shorthand

At school some of us learned shorthand: a short, quick way of writing. I think teams could have shorthand for AI tools too. A few short phrases the tool understands because they are mapped to a full command or skill. In Claude Code these are custom slash commands and skills.

One thing I had to correct in my own thinking: a shorthand that expands into a full prompt still sends the full prompt, so it saves typing, not tokens.

The token saving comes from loading detail only when it is needed. A skill keeps its instructions in a file and loads them for the task that needs them, instead of everyone pasting the same long context into every chat.

The hard parts

Setting it up is probably the hardest part. Then managing it: who owns each file, and who checks it is still right? And knowing when to stop. Every file you add costs context and can go out of date.
