Lay of the land: an LLM that reads your incidents

5 min read

First, the name. In security, LOTL usually means living off the land: attackers using tools already on a system. This is not that. Lay of the land means what it says: a survey of everything that happened over a period of time, and what it was most likely linked to.

I sketched it as a command: lotl --past-day, lotl --3h. It pulls every incident, alert and anomaly in that window into one report, which can also go to email or a team channel. Try it:

It comes from combining my background in infrastructure with LLMs.

How I set it up

At work I have set up a version of this. The assistant has MCP connections to New Relic, PagerDuty and Rollbar, plus access to our GitHub environment. Our internal tools already monitor CPU and memory, so it can watch those too.

How it follows a spike

When something spikes in New Relic, it checks what the spike is likely linked to, one layer at a time:

If the spike is inIt looks at
PHPThe web servers
External servicesKubernetes
RedisRedis, front end and back end
DatabaseThe SQL instances, for a CPU or memory spike

Something links to something that links to something else. It is a cascade.

Patterns

The other half is pattern matching. Every company has patterns of events. Lay of the land watches what happened over previous days and asks: where has this pattern happened before? It also checks what code was released that day and matches the release against the likely cause. The aim is to say "this is the likely issue" and, over time, to predict when it will happen next.

What I'm still working out

  • How the report shows its evidence: which alert, which release, which timestamp.
  • What it says when it is not sure, and what stops it naming a cause that is not in the data.
  • Whether the MCP connections should all be read-only, and what monitoring data should reach the model at all.
  • Log lines are partly written by outside users. One could carry an instruction the model then follows.
